WDL HEAD MIGRATION - XERCES / CHESSBOT
=======================================
Scalar value head (-1 to 1) → 3-vec WDL head [w, d, l]
Q = w - l  |  contempt = -c * p_draw when STM is winning
vscale moves from Python inference to C++ (applied to Q = w-l, not to draw prob)

All existing .tfrecord.gz training data is INCOMPATIBLE and must be regenerated.
All existing model checkpoints (.pt files) are INCOMPATIBLE (output shape changes).

PART 3 — Retraining Plan
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Model compatibility:
  - All existing .pt checkpoints are INCOMPATIBLE. The value head output shape
    changes from (B,1) to (B,3) and the final layer loses tanh. Cannot fine-tune;
    must train from scratch on new TFRecords.

  - Strategy: save existing best checkpoint as a "policy-only" baseline.
    The policy head is identical and unchanged — weights can be transferred
    manually if desired (load checkpoint, replace vout layer, train only value
    head for a few epochs, then unfreeze all).

TFRecord data:
  - All existing .tfrecord.gz files are INCOMPATIBLE. The value_out feature
    changes from a scalar float32 to a 3-float float32. The TF dataset pipeline
    will fail to parse old files with the new schema.

  - DO NOT mix old and new .tfrecord.gz files in the same BOOTSTRAP_TFREC_DIR.
    Use a new output directory.

  - Old game .pkl.gz files are COMPATIBLE and can be reprocessed. They will
    not have root_wdl (that field is only written by the new looper), so
    build_bootstrap_tfrecords.py will fall back to to_wdl(z) for value targets.
    This is fine for bootstrapping the first new model.

  - New self-play games generated with the new engine will have root_wdl saved
    in the pkl, giving richer WDL targets blended with the game outcome.

Recommended sequence:
  1. Implement and test C++ changes (pyfastchess). Rebuild.
  2. Implement looper.py and model changes. Verify raw_cache_bulk_insert accepts WDL.
  3. Run build_bootstrap_tfrecords.py against existing pkl.gz game data into a
     NEW tfrec dir. This regenerates all training data with WDL targets.
  4. Train a new model from scratch with bootstrap_model_async_tfrec_pt.py.
  5. Once the new model is deployed in self-play, new games will have root_wdl
     in pkls, improving training signal over time.

  5. bootstrap_model_async_tfrec_pt.py reads .tfrecord.gz via pretrain.make_dataset(),

PART 5 — Watch out for
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. STM flip correctness
   RawEntry stores WDL in STM-POV (inference is always STM-made-white).
   CacheEntry and backprop use WHITE-POV. The flip (swap wdl[0]/wdl[2]) must
   happen exactly once, at the two raw-cache read sites (Step 5). Do not flip
   twice. Terminal values are already white-POV and do not need flipping.

2. vscale is no longer applied in Python
   The old line `value = np.clip(outs[1] * vscale, -1, 1)` must be removed from
   the inference path entirely. If left in, vscale is applied twice (Python + C++),
   collapsing the effective Q range toward 0. Verify by checking that raw WDL
   values from inference arrive at C++ as softmax probabilities summing to 1.

3. Priors cache (CacheEntry) invalidation
   CacheEntry.wdl replaces CacheEntry.value. The in-memory cache is cleared on
   engine restart, so no migration is needed. But if any code serialises/deserialises
   CacheEntry to disk it will break. Verify no persistent priors cache is in use.

4. PyTorch cross_entropy with soft targets
   F.cross_entropy(input, target) with float target requires PyTorch >= 1.10.
   Target shape must be [B, 3] float, NOT [B] int (class indices).
   If target does not sum to 1 the loss is still valid but interpretation changes.
   Add an assertion or normalise targets during data loading as a safeguard.

5. contempt gate uses parent Q, not child Q
   The gate (parent_q > 0) checks whether the SELECTING node thinks it is winning,
   not the child being evaluated. This is intentional: contempt is a property of
   the position's overall evaluation, not a per-move decision. Do not change this
   to (q > 0) — it would cause contempt to apply inconsistently to different lines.

6. to_wdl(x) for scalar MCTS Q fallback
   to_wdl(x) = [max(x,0), 1-|x|, max(-x,0)] is valid for x in [-1,1] but
   saturates at the extremes (Q=1.0 → [1,0,0] with zero draw mass). This is
   intentional and correct. For positions the tree thinks are nearly decided, the
   draw component of the training target should be near zero.

7. Old games missing root_wdl
   Games played before this migration have no root_wdl in their pkl. The fallback
   to_wdl(z) uses the GAME OUTCOME, not the tree's belief at that ply. This is
   a coarser signal but was the only signal available under the scalar head too.
   It is safe to mix old and new game pkls in the same build_bootstrap run.

8. draw probability in Q_draw vs wdl[1]
   ChildDetail.Q_draw is the TREE-AVERAGED draw probability (accumulated over all
   backprops through that node). ChildDetail.wdl is the LEAF WDL (what the NN
   returned at that node's expansion). They are different. For contempt, C++ uses
   Q_draw (tree-averaged, more stable). For training targets, use root_wdl (leaf
   WDL at root expansion). For display/telemetry, both are useful.

9. TFRecord shard mixing
   Do NOT point BOOTSTRAP_TFREC_DIR at a directory containing a mix of old
   (scalar value_out) and new (3-float value_out) shards. TF's FixedLenFeature
   will silently parse old scalar shards as if value_out=[scalar, 0, 0] is wrong
   but may not crash immediately. Use a clean output directory.

10. Weight transfer from old models
    The policy head weights (emb/pos/blocks/pol) are identical between old and new
    models. If you want a head-start, you can load an old checkpoint, add the new
    vout layer (3 outputs), and fine-tune with value loss only for a few epochs
    before full training. This is optional but can save several epochs of warmup.
